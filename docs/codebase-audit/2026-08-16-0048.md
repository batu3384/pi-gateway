## CA-001 | Major | Correctness | scripts/pi/recover-readonly-root.sh:184

**Kanıt:** `setup-docker-ssd.sh` çağrısı `|| log "WARN: docker SSD restore atlandi"` ile sarılı; script başarısız olsa bile `run_compose_recover` ve degraded clear gate devam eder. `setup-docker-fallback.sh` sonrası daemon `/var/lib/docker` iken SSD marker hâlâ `/mnt/ssd/.docker-data-root` üzerinde kalabilir.

**Neden:** Watchdog/health yolu hotplug'u bypass eder; Docker SSD restore sessizce atlanırsa stack "healthy" görünür ama imajlar SSD'de, daemon SD root'ta — pull storm, SD doluluğu, container start fail.

**Yön:** `setup-docker-ssd` başarısızlığında recover exit 1 veya degraded flag koru; `docker info` root doğrulaması clear gate öncesi zorunlu kıl.

## CA-002 | Major | Correctness | scripts/pi/setup-docker-ssd.sh:102

**Kanıt:** `bring_up_stack()` tam `docker compose up -d` çalıştırır (`setup-docker-ssd.sh:102-108`). Aynı recover tick'te `recover-readonly-root.sh:203-208` tekrar `run_compose_recover` çağırır.

**Neden:** Çift compose up gereksiz container flap, kısa DNS kesintisi, race (özellikle degraded→full geçişte). Üst düzey orchestration tek sorumluluk ihlali.

**Yön:** `setup-docker-ssd.sh`'e `SKIP_COMPOSE_UP=1` modu; recover-ro tek compose up sahibi olsun. Veya setup yalnızca daemon.json migrate + restart.
