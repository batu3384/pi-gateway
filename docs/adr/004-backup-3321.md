# ADR-004: Backup 3-2-1

## Status

Accepted

## Context

Restic repo lived only on the same SSD as live data. Disk failure destroyed “backups”.

## Decision

- On-Pi restic → SSD path (encrypted, excludes repo recursion).
- **Offsite required**: `make backup-pull` (Mac) copies restic repo + config snapshots.
- SLA: `OFFSITE_BACKUP_MAX_AGE_DAYS=7` (default); `LOCAL_BACKUP_MAX_AGE_HOURS=26` for config snapshots (`~/pi-gateway/backups/`).
  - Mac `doctor`: missing stamp = warn; stale = fail (unless `WEAK_BACKUP_OK=yes`).
  - Pi `health-check`: offsite + `local-backup-failed/stale`; `systemctl is-failed pi-gateway-backup.service` → SLO fail.
- `backup.sh` runs `fix-config-perms` before rsync; runtime `AdGuardHome.yaml` excluded (restore via render + apply).
- Restic Docker image pinned (0.19.1); `backup-pull` uses same image for `check` when Docker is available.
- Corrupt repo: `restic-repair.sh`; unrecoverable → `/mnt/ssd/pi-gateway-recovery/` + fresh init + `backup-pull`.
- Stamp files: `$MAC_BACKUP_DEST/.last-success` and `/var/lib/pi-gateway/last-offsite-backup`.

## Consequences

- SSD alone is **not** a backup.
- Operators should run `make backup-cron`.
- Future: `RESTIC_OFFSITE_ENABLED=true` copies to B2/R2 after local backup (S3-compatible). Mac `backup-pull` remains recommended.
